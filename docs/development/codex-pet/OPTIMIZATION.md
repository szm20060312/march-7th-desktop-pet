# 优化与验收流程

## 推荐优先级

1. 加强 `022.5` 的轻微右向提示，同时保持“向上”为主。
2. 加强 `337.5` 的轻微左向提示，同时保证它只比 `000` 少一步。
3. 平滑 `180 → 202.5` 与 `315 → 337.5` 的头部位置变化。
4. 检查所有状态中相机、腰侧装备和飘带的连接关系。
5. 在不损失 192 × 208 可读性的前提下，恢复更多参考图服装细节。

## 单次优化流程

### 1. 定义问题

记录：

- 受影响状态或方向
- 正常显示尺寸下看到的具体问题
- 当前通过的属性，必须保持不变
- 修复后的可验证标准

示例：

> `337.5` 的上向语义正确，但水平左向提示较弱。重做完整第 10 行，使鼻尖和瞳孔保留轻微画面左偏，同时保持脚底、相机、比例及 `270 → 000` 连续性。

### 2. 选择修复范围

- 标准动作问题：重做完整状态行。
- 视线问题：重做所在的完整 8 帧方向行。
- 确定性分帧问题：先修正提取/注册，不要立即重生成图像。
- 色键边缘问题：只使用最终统一去色键流程，不做逐格涂改。

禁止：把独立生成的单格直接拼入最终新图集。

### 3. 增量验证

每个候选版本至少检查：

- 帧数与顺序正确
- 身份、服装、配色和配件一致
- 无裁切、重叠、空帧、漂浮组件
- 基线、尺寸和身体锚点稳定
- 动作语义正确
- 方向卡位遵循画面坐标，而非角色自身坐标

### 4. 完整发布门槛

- `spritesheet.webp` 为 `1536 × 2288`
- WebP 为 RGBA，透明背景
- `pet.json` 包含 `spriteVersionNumber: 2`
- 9 个标准动作行全部通过视觉播放检查
- 四个方向基准明确无歧义
- 16 个方向完成标签语义检查
- 三份隔离盲测结果合并后，水平和垂直基准方向通过
- 连续性报告已人工复核
- 最终独立视觉 QA 为 `pass`
- 安装目录中 `pet.json` 与 `spritesheet.webp` 同时存在

## 发布和回滚

建议以后把每次通过验收的产物放在：

```text
releases/<version>/
  pet.json
  spritesheet.webp
  contact-sheet.png
  look-directions.png
  validation.json
  direction-semantics.json
  CHANGELOG.md
```

发布前先复制当前已安装版本作为回滚包。只有新版本全部通过门槛后，才替换 `~/.codex/pets/march-7th/` 中的两个运行文件。
