## 已实现的技术范围

- **M5-A 专注陪伴**：Rust 只管理一个会话，支持开始、暂停、继续、提前结束、放弃、睡眠/时钟异常恢复和一次性自然完成；设置页可手动操作。专注进行时日常提醒仍到期并保留待处理，但自动气泡静默。自然完成在允许的活动时段、非全局稍后且无手动提醒视图时，复用现有气泡提示一次；否则结果留在固定入口。完成气泡可查看合并的待处理数，不补弹每个历史周期。两角色沿用现有动作和短句。
- **M5-B 当前一件事**：会话开始可选一个短任务名，完成/放弃各只反馈一次；任务结果与专注计时独立，不保存任务列表、项目或统计。`focus.json` 内层 v1 可迁移到 v2；外层四项数据集/备份维持 v2，旧备份可读。任务正文只在设置页和用户主动导出的本地备份里；导入预览、默认诊断及角色响应不带名称。
- **M5-C 分发技术准备**：已有未签名 Windows 当前用户 NSIS 与 Mac Apple Silicon DMG 的原生 CI 候选流程、完整提交/程序/安装包哈希核对、同提交配对及依赖许可清单。它保留原来的可直接运行回归包，不创建公开 Release、自动更新、签名或付费资源。

架构边界是：前端只做表现与非权威秒数插值；专注进度由 Rust 单一服务负责，状态先原子写入成功再发布。四项配置（位置、角色、提醒、专注）由一个活动数据集指针整体选择；旧 v1 数据与备份有显式迁移及保护。提醒和专注共享一个气泡呈现协调器，角色目录不承载计时或数据写入。细节见 [架构说明](ARCHITECTURE.md)、[数据集迁移](M5-DATASET-V2.md)、[当前一件事](../../M5-CURRENT-TASK.md) 与 [分发准备](DISTRIBUTION-READINESS.md)。

**仍需进行**：所有者在 Windows、协作者在 Mac 对选定的**同一完整提交**按同一清单实测窗口、角色、提醒、专注、任务、文件对话框、重启恢复、睡眠与升级回退；角色引导改动应以包含该改动的新包验收。Mac Spaces 与先前一次配置目录锁的间歇失败仍须实证排查。所有者还需验收两位角色动作和短句，并用约两周的少量朋友试用判断“提醒有用且不烦”及任务相对纯计时的额外价值。素材分发范围、签名、预算和维护责任未确定前不公开发布。

## Windows 初步反馈与后续候选

所有者已安装并启动文档提交 `3afbee6` 的 Windows 未签名候选，初步表示“目前来看没有异常”，但认为互动性和功能性不足，尤其通用提醒窗缺少角色参与、两位角色台词应符合各自性格。这是有价值的方向反馈，不是完整清单、长期稳定性或提醒价值验收。后续角色引导提醒候选加入到期动作、分类型角色对白和贴身可操作气泡；三月七采用活泼亲近口吻，雷电将军按所有者选择采用克制正式口吻。其源码、本地测试和浏览器排版观察与旧 `3afbee6` 安装结果分开记录；新候选仍须取得自己的同提交双平台 CI、Windows/Mac 原生 GUI 和真人使用反馈。

2026-09-24 后续所有者反馈否定了带头像和按钮的独立提醒卡，并批准“桌面角色亲自递杯、原有小对话框只说话、点角色再显示双操作”。这版候选采用两角色独立四帧递杯资源；默认自动展示窗口透明且鼠标穿透，点击后由 Rust 核对当前展示 ID 才开放操作。此前 `6be5981` 的安装观察仅属于旧版提示窗，不能视为新递杯候选的桌面验收。新代码的本地检查与双平台 CI、安装实测、真人反馈分别记录。

所有者在 `8fdda2c` Windows 安装版看到递杯，但提醒台词未看清、收尾突兀；普通点击台词正常。新修订让自动到期台词持续到原生展示结束，把自动截止从 10 秒延长到 20 秒，并倒序收杯后清除台词。此修订的本地测试与后续 CI 只能证明规则实现，不能替代同提交的 Windows/Mac 真人观感复测；旧候选的反馈不能标为问题已解决。

`fefed5a` 的所有者截图确认台词清楚，但未点击前的独立透明窗口在 Windows 上呈黑色矩形，且淡出仍有闪现、对白和操作时间偏短。后续修订取消未点击时的可见原生窗口，点击后才显示操作；把未点击时展示延至 45 秒，点击后由服务端给当前展示 60 秒，角色图集切换改成两层淡入淡出。此段是新候选设计与本地检查，不代表截图问题已在实机消失。
