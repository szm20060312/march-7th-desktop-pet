# G7-B3c2：从本地备份安排下次启动导入

设置窗口“本地数据 → 导入备份…”打开系统原生文件选择框。选定后，Rust 在后台最多读取 2 MiB 加一字节，通过既有备份格式和三个 Store 的验证器检查内容；界面只收到角色、位置是否保存、三类提醒开关与间隔、待处理数量、暂停和安静期等有限摘要，以及当前预览的一次性票据。外部路径和原始配置不进入 WebView，也不写入日志。

用户必须核对预览并点击“确认导入”，才会调用 `DataDirectory::prepare_import`。确认使用 Rust 内存中冻结的候选，不重新读取外部文件。成功只安排下次启动整体切换；当前角色、提醒与位置保持原状，不自动重启。原平铺文件和旧数据集仍由 G7-B2 保留。已有 pending 时新确认会被拒绝，提示先正常退出并重开；本版不提供取消已安排导入。

导出与导入对话框共用一个窄 gate，不会同时打开。普通隐藏设置窗口会立即撤销旧票据和前端等待，但保留原生对话框租约直到其真实回调；因此旧对话框仍在屏幕上时，再次点击本地数据操作会提示稍候。窗口真正销毁或应用退出时释放旧租约，避免插件不再回调造成永久忙碌；旧回调仍由票据隔离，不能触及新会话。锁定的 [Tauri Dialog 2.7.3 源码](https://docs.rs/tauri-plugin-dialog/2.7.3/src/tauri_plugin_dialog/desktop.rs.html)中异步选择/保存 API 不返回主动取消句柄。销毁父窗口后的 OS 对话框实际消失行为仍需 Win/Mac 实机验收；若某平台保留孤立对话框，它与新窗口可能短时重叠，此时以避免永久锁死和拒绝旧结果为当前取舍。

确认已明确发出后，即使窗口随后关闭，后台准备仍可完成，但旧结果不再写回新窗口。取消预览不安排导入；准备失败保留冻结预览用于重试，原数据不受影响。提醒设置草稿独立于本地备份操作。

错误只通过固定代码映射成提示：无法读取、文件过大、格式或版本不支持、校验失败、内容不合法、已有 pending、准备写入失败等。备份摘要用于偶然损坏检测，不能证明来源真实性；只导入自己可信的文件。没有增加通用 JS 文件权限、账号、云同步或自动更新。

自动检查涵盖 gate 互斥、关闭后迟到回调、冻结候选、确认与次启、已有 pending/准备失败、前端确认/取消/草稿隔离，以及类型和构建。浏览器布局仅在本地静态预览样例中检查了普通窗口与 320×300 窄窗口的滚动、确认按钮可达；原生 Windows/macOS 选择框及真实备份的导出→导入→重启回读，仍需同提交双平台实机验收。测试只使用独立临时数据，不触碰用户配置。
