# M0 双平台共用回归清单

每个平台各填一份结果模板，同一提交。状态只能是“通过／失败／待测／无设备／不适用”，每个结论注明观察。以下操作都在真实桌面进行，不用网页预览代替。

## 1. 环境与启动

- 记录完整提交 SHA、构建运行链接、平台、系统版本、芯片/CPU、内存、显示器排列和各自缩放。
- 校验包内文件；退出旧实例；启动一个新实例并记录 PID。
- 确认角色显示、背景透明、无边框、置顶；后面放一个普通窗口观察，不应出现黑/白矩形。
- Windows：不出现普通任务栏窗口按钮。Mac：记录当前桌面/空间，不用其他空间行为推断通过。

## 2. 待机与注视

- 将鼠标放到角色中心约 20 个逻辑像素内，观察待机动画连续循环，没有空白或跳到其他动作。
- 将鼠标移出中心，确认方向变化；鼠标静止时方向稳定。
- 按画面坐标检查 16 个方向：从正上方 0° 起顺时针，每 22.5° 一个方向。
- 逐项记录：0、22.5、45、67.5、90、112.5、135、157.5、180、202.5、225、247.5、270、292.5、315、337.5。
- 图集既有的 22.5° 与 337.5° 水平提示较弱是已知视觉限制；记录“难区分”及表现，不自动把它当新平台错误或直接算通过。
- 可录制鼠标绕角色一周的短视频，用于区分方向计算和素材语义问题。

## 3. 拖动与恢复

- 向右拖动播放向右跑动；向左拖动播放向左跑动。
- 左右反复转向，方向能跟上；没有注视帧插入、眼神抖动或空帧。
- 先向左再仅上下拖动，沿用左方向；先向右再上下拖动，沿用右方向。
- 停止移动后很快恢复注视或待机，目标约 160 ms。人工记录是否明显延迟/闪烁；精确时序由自动测试及必要录像检查证明，不能凭感觉填写测量值。
- 非主鼠标键不应触发拖动。注意：当前透明留白也属于拖动区域，此项不是新功能。

## 4. 缩放与显示器

- Windows 分别在可用的 100%、125%、150%、200% 缩放下重复主要方向和拖动测试，记录应用重启前后结果。无法选择某档则注明原因。
- Mac 在设备实际提供的默认及另一种缩放选项下重复主要交互；不要把 Mac 显示设置硬写成 Windows 的百分比。
- 有第二显示器时：往返拖动、左侧负坐标/上方负坐标、不同缩放、跨屏后方向与尺寸。
- 无第二显示器时标“无设备”；不以代码或单屏结果代替混合 DPI 实测。
- 当前不保存位置、无显示器恢复功能。那些是 M1 目标，不纳入 M0 已完成项。

## 5. 性能与稳定性基准

- 使用 Windows 任务管理器或 macOS 活动监视器，记录本次进程与相关 WebView 子进程；写明工具显示的 CPU/内存口径，避免跨系统直接比较百分比或内存定义。
- 启动后预热约 1 分钟；静止约 5 分钟，记录 CPU 和内存的观察范围。
- 连续移动鼠标/拖动约 1 分钟，记录响应、CPU 和内存；然后静止检查是否回落。
- 有时间时保持运行至少 60 分钟，在开始、15、30、60 分钟记录状态。记录真实持续时长，不足一小时保留长测待完成。
- 睡眠唤醒后检查角色和交互能否继续；发现异常说明是否必须重启。
- 记录卡顿、持续占用、窗口消失、重复实例、异常退出或内存持续增长；没有测量数据时不写“零占用”或“无泄漏”。

## 6. 退出与汇总

- 按包内 README 的当前退出方式关闭**本次进程**，确认角色消失；再次启动确认正常。
- 本次包只能验证运行行为；开发热更新清理需开发环境另测，普通测试者可标“不适用（开发者待补）”。
- 同一提交的 Windows/Mac 结果均回收后，汇总失败、待测和设备缺口，再决定能否关闭 M0。收齐包或跑完 CI 不能自动关闭 M0。

问题优先级：P1 无法启动/正常使用、无法关闭或严重持续占用；P2 方向、拖动、透明或恢复等功能错误；P3 轻微视觉差异。无法复现的问题也保留观察，不猜根因。
