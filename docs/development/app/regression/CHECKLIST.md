# 当前构建双平台共用回归清单（M0 / M1 / G4 / G6）

每个平台各填一份结果模板，同一提交。状态只能是“通过／失败／待测／无设备／不适用”，每个结论注明观察。以下操作都在真实桌面进行，不用网页预览代替。

## 1. 环境与启动

- 记录完整提交 SHA、构建运行链接、平台、系统版本、芯片/CPU、内存、显示器排列和各自缩放。
- 校验包内文件；退出旧实例；启动一个新实例并记录 PID。
- 确认角色显示、背景透明、无边框、置顶；后面放一个普通窗口观察，不应出现黑/白矩形。
- Windows：不出现普通任务栏窗口按钮。Mac：记录当前桌面/空间，不用其他空间行为推断通过。

## 2. 待机与注视

- 将鼠标放到角色中心约 20 个逻辑像素内，观察待机动画连续循环，没有空白或跳到其他动作。
- 将鼠标移出中心，确认方向变化；鼠标静止时方向稳定。
- 按画面坐标检查 16 个方向：从正上方 0° 起顺时针，每 22.5° 一个方向。
- 逐项记录：0、22.5、45、67.5、90、112.5、135、157.5、180、202.5、225、247.5、270、292.5、315、337.5。
- 图集既有的 22.5° 与 337.5° 水平提示较弱是已知视觉限制；记录“难区分”及表现，不自动把它当新平台错误或直接算通过。
- 可录制鼠标绕角色一周的短视频，用于区分方向计算和素材语义问题。

## 3. 拖动与恢复

- 向右拖动播放向右跑动；向左拖动播放向左跑动。
- 左右反复转向，方向能跟上；没有注视帧插入、眼神抖动或空帧。
- 先向左再仅上下拖动，沿用左方向；先向右再上下拖动，沿用右方向。
- 停止移动后很快恢复注视或待机，目标约 160 ms。人工记录是否明显延迟/闪烁；精确时序由自动测试及必要录像检查证明，不能凭感觉填写测量值。
- 非主鼠标键不应触发拖动。注意：当前透明留白也属于拖动区域，此项不是新功能。

## 4. 缩放与显示器

- Windows 分别在可用的 100%、125%、150%、200% 缩放下重复主要方向和拖动测试，记录应用重启前后结果。无法选择某档则注明原因。
- Mac 在设备实际提供的默认及另一种缩放选项下重复主要交互；不要把 Mac 显示设置硬写成 Windows 的百分比。
- 有第二显示器时：往返拖动、左侧负坐标/上方负坐标、不同缩放、跨屏后方向与尺寸。
- 无第二显示器时标“无设备”；不以代码或单屏结果代替混合 DPI 实测。
- 当前构建已实现位置保存与显示器恢复，按下方 M1 项验收；历史 M0 包以其原提交随包清单为准，不追溯宣称新增能力通过。

## 5. 性能与稳定性基准

- 使用 Windows 任务管理器或 macOS 活动监视器，记录本次进程与相关 WebView 子进程；写明工具显示的 CPU/内存口径，避免跨系统直接比较百分比或内存定义。
- 启动后预热约 1 分钟；静止约 5 分钟，记录 CPU 和内存的观察范围。
- 连续移动鼠标/拖动约 1 分钟，记录响应、CPU 和内存；然后静止检查是否回落。
- 有时间时保持运行至少 60 分钟，在开始、15、30、60 分钟记录状态。记录真实持续时长，不足一小时保留长测待完成。
- 睡眠唤醒后检查角色和交互能否继续；发现异常说明是否必须重启。
- 记录卡顿、持续占用、窗口消失、重复实例、异常退出或内存持续增长；没有测量数据时不写“零占用”或“无泄漏”。

## 6. 退出与汇总

- 按包内 README 的当前退出方式关闭**本次进程**，确认角色消失；再次启动确认正常。
- 本次包只能验证运行行为；开发热更新清理需开发环境另测，普通测试者可标“不适用（开发者待补）”。
- 同一提交的 Windows/Mac 结果均回收后，汇总失败、待测和设备缺口，再决定能否关闭 M0。收齐包或跑完 CI 不能自动关闭 M0。

问题优先级：P1 无法启动/正常使用、无法关闭或严重持续占用；P2 方向、拖动、透明或恢复等功能错误；P3 轻微视觉差异。无法复现的问题也保留观察，不猜根因。


## 7. M1 托盘、非聚焦与位置恢复（两平台逐项同验）

- 检查显示、隐藏、重置位置、交互模式、点击穿透和正常退出；菜单只勾选一个模式，托盘隐藏图标区域也可找到恢复入口。
- 正在其他应用输入时显示/重置桌宠，前台焦点不被抢走；隐藏后从托盘恢复，关闭窗口不杀死常驻进程。
- 开启穿透后点击桌宠区域，底层应用仍接收输入；从托盘恢复交互，再试拖动。隐藏/显示与角色切换均不改变所选模式。
- 拖至工作区边缘，等待保存状态，再正常退出重启，检查相对位置恢复；模式/隐藏状态不保存，启动恢复交互与可见状态。
- 在低到高、高到低缩放、左/上负坐标屏之间重复拖动、重置和重启恢复；记录实际尺寸、可达性及是否闪现在旧位置。
- 拔掉/重排已保存显示器后启动，或运行中改变显示器拓扑，确认角色回到可达工作区；超小工作区及超大窗口单独记录，不能用单屏代替。
- 开发者在隔离配置备份上测试 desktop-state.json 损坏/未来版本、写入失败和恢复；源文件保留、状态提示真实，不把模拟故障算实际设备通过。

## 8. G4 两角色互动、选择与失败边界（两平台逐项同验）

- 无角色配置时启动三月七，托盘显示两项且互斥；选择雷电将军，状态显示已保存，正常退出重启仍为雷电；启动/切换不主动说话或播放互动动作。
- 每个角色分别检查待机、16方向、单击挥手、双击跳跃、点击短句、拖动中断与恢复；透明未用行不能被播放，台词与最终观感由所有者确认。
- 快速反复切换并再次选择同一项，最终显示与托盘有效选择一致；不得创建重复动画循环、拖动监听或提醒时钟。乱序快照/事件、销毁中的迟到读取/监听由开发者自动测试记录，不能仅凭快速点击宣称完全覆盖。
- 穿透状态从托盘换角，确认穿透、位置、显示/隐藏及其他应用状态不变；隐藏时换角不自动显示，不抢焦点。
- 开发者在隔离配置备份上模拟未知角色 ID：回退默认且提示未覆盖，启动不修改源文件，显式选择默认后才保存；损坏/未来版本或不可读配置本次仅临时选择，明确显示“角色：仅本次有效”。
- 模拟角色写入/备份失败：有效角色与文件保持旧值，托盘显示失败；恢复写入条件后再次选择可成功。检查日志不得包含原始配置内容。
- 模拟目标图集读取失败：旧角色保留，错误短暂可见且日志可诊断；再次选择同一角色可重试。不要将屏幕保旧误记为 Rust 已回退。
- 在角色保存中退出：后续排队请求取消，迟到结果不恢复 UI；已开始写入可能完成，重启以磁盘完整配置为准。角色 IO 不阻塞 UI，也不取代 desktop 正常退出的位置保存。

以上新增项及所有者双角色最终观感/台词验收均先记“待测”，独立审查、自动测试、CI、原生包、浏览器预览、实机观察分别记录，不能自动关闭 M2/G4。

## 9. G6 提醒、非聚焦窗口与恢复（同提交两平台逐项）

- 在隔离测试配置中首次启动：三项全关，无提醒气泡或设置窗；从托盘确认并保存后才启用。全部本地、无账号，不以默认分钟数当健康建议。
- 打开设置、编辑不保存、关闭并重开：草稿丢弃、真实设置重新显示。连续打开/关闭、建窗或布局期间关闭、退出：旧回调不能再弹出窗口或恢复进程。设置仅由手动打开聚焦。
- Mac 在另一应用保持输入焦点时，第一次点击角色、第一次拖动角色、第一次点击提醒的完成/稍后/收起分别检查；第一次输入应有效且提醒不抢焦点。Windows 同样检查按钮与焦点，不用配置/模拟测试代替。
- 隐藏角色、开启角色穿透后等到提醒：独立气泡可操作，角色状态不变。完成/稍后反馈只播放一次；换两角色后分别测试且规则不重置，不同时收到系统 toast/声音。
- 自动气泡约 10 秒无回应收起，pending 保留但不连续重复；托盘可查看待处理，空集合也显示页面。原生关闭和收起不能完成事项。旧自动收起不能关闭新手动查看。
- 同批次新增/完成事项时按钮位置尽量稳定；多行、错误、很矮/很窄视口可滚动并够到所有按钮。负原点、高低不同缩放、角色在边缘/第二显示器、运行时拔屏/重排时两窗口保持可达；设置窗不超出高 DPI 工作区。
- 暂停/恢复、活动时段、全局稍后及新到期合并、睡眠/唤醒和正常重启逐项记录。托盘勾选只据实际状态，隐藏角色不是暂停；不以点击完成推断真实健康行为。
- 开发者在隔离配置测试加载、只读/损坏/未来版本、未保存/恢复、无效时钟，以及建窗/显示/位置失败：提示真实、原文件保留、pending 可从托盘恢复。策略故障注入与原生故障观察分别记录，不能互相代填。
- 至少记录一个真实有用或打扰情境及是否愿意继续开启；无实际使用就留空。实现、独立审查、同提交构建、浏览器模拟、双平台实机和用户反馈分开；本清单不自动关闭 G6/M3。
