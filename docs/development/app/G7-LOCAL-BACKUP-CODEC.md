# G7-B3a 本地备份包 v1 编解码

本阶段只有纯 Rust 编解码接口，尚未接入当前运行状态快照、文件选择、设置页面或导入确认。不能把本阶段称作用户可用的导出、导入或迁移功能。

备份是一个不超过 2 MiB 的 JSON 文件，固定为 `format: "march7-local-backup"`、`schemaVersion: 1`、`createdAtUtcMs`、`files`、`sha256`。`files` 只含 `desktopJsonBase64`、`charactersJsonBase64`、`remindersJsonBase64`；桌面状态允许 `null`，后两项必有。每项编码现有 Store 的完整原始 v1 JSON 字节，不重新序列化业务文件。缺省桌面在摘要和后续数据集准备中使用 B2 已定义的 `{"version":1,"placement":null}`，但备份包里仍是 `null`。顶层和 `files` 都拒绝未知或重复字段；读取时限制包大小，并要求标准、规范的 Base64。

`sha256` 复用 G7-B2 的固定顺序：对桌面、角色、提醒依次加入固定文件名 UTF-8 字节、该文件字节长度的 `u64` 小端表示、文件原始字节，然后计算 SHA-256 的 64 位小写十六进制文本。它只检测意外损坏，不鉴别备份来源，也不覆盖创建时间元数据。解码依次检查包大小、格式、版本、时间和编码，再由三个 Store 的原有导入规则验证原始字节并核对摘要：未来文件版本、未知角色、不合法的提醒配置或进度会被拒绝。返回值只含冻结的候选字节与最小预览摘要，预览没有原始配置、路径或任意外部文件名。

文件格式固定覆盖当前三个 Store；将来若专注或任务陪伴需要持久化，必须明确升级备份格式与导入兼容规则，不能悄悄把新数据塞进 v1 或让 v1 导入静默丢失它们。实际导出资格、一次性预览票据、原生文件对话框、下一次启动生效及双平台实机验收留给后续阶段。
