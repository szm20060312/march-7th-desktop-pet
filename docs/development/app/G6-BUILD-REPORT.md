## 本次实现

托盘可打开提醒设置、查看待处理、暂停/恢复。喝水、起身活动、休息眼睛首启全部关闭，各有开关与间隔；活动时段、全局稍后与保存状态由原生后台管理。设置草稿不会被后台更新覆盖，应用但未保存、只读和运行错误有独立提示。

独立气泡支持分别完成、统一稍后和收起；自动收起保留待处理，不反复弹出旧事项。窗口按需创建，提醒不主动聚焦，角色穿透与显示状态独立。角色回应只从原生操作事件送出一次；切换角色不修改提醒进度。没有另一套系统通知、账号或遥测服务。

## 本轮技术取舍

- 使用两个具体、按需创建的设置/提醒窗口，避免启动时加载无用页面；代价是维护首次显示的就绪与位置协调。
- 主角色与提醒显式接收 Mac 首次鼠标点击，同时保持不聚焦策略；配置依据不替代实机验证，若平台实际行为不同需要适配层修正。
- 正常气泡中保留已处理行并追加新行，避免完成按钮移位；代价是本批次暂时保留占位。极小工作区以滚动可达为回退。
- 用窗口代次与展示 ID 做渲染就绪握手，防止空白或旧视图被显示；增加一个仅用于界面生命周期的接口，不把握手当成人已经看见。
- 按锁定 Tauri 版本的 Windows 限制异步构建隐藏窗口，再把后续窗口效果放回主线程；错误围栏仍需原生验收，策略回归不能证明真实 WebView 永不失败。
- 设置关闭改用原生协调入口，先取消待完成的重开再隐藏；代价是一个窄的接口和相关回归，设置控制器对用户的关闭行为保持不变。
