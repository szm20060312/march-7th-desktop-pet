# G4 双角色与互动边界

本页记录角色实现与原阶段验证。后续集成候选 `4cb11dd` 的 Windows/macOS CI 与原生包核对已通过；两平台点击、切换、动作和短句的实机及所有者最终验收仍未完成，M2 未关闭。见 [当前验证记录](ARCHITECTURE-VALIDATION.md)。

## 当前已实现

- `src/characters/catalog.json` 是两角色唯一的编译期数据源，信封结构为 `{ defaultId, characters }`。三月七使用稳定 ID `march-7th`，雷电将军使用稳定 ID `raiden-shogun`；`march-7th.ts` 只保留兼容导出，不复制配置。
- 两份内置图集都按 192×208 单元格、8 列、11 行校验。待机、左右移动、挥手、跳跃和 16 向注视只使用 row 0–4 与 row 9–10，不请求透明的 row 5–8。
- 角色模型的优先级为 `movement > one-shot > look > idle`。wave/jump 从首帧播放一次，以注入的单调时钟直接计算当前帧；缺少动作资源时复用现有 idle clip 播放一个完整周期，再恢复注视。实际窗口位移或拖动会中止互动，移动中输入不会排队。
- 主按钮释放后等待 300 ms 区分单双击；第二次释放需同时满足 300 ms 和 6 逻辑像素边界。移动达到 6 逻辑像素才释放 pointer capture 并发起一次原生拖动。cancel、lost capture、blur 和销毁都会清理未完成输入。
- click、doubleClick、reminderCompleted、reminderSnoozed 是明确的情境回应入口。每个角色每个情境有两句短句，按角色内顺序轮换；短句显示 3 秒，连续回应替换旧文本，拖动、停止或换角立即清除。提醒两种情境目前只提供类型化响应能力，没有新增提醒入口或提醒时钟。
- 主窗口仍为原生配置的 240×260。顶部预留 36 px 短句区，角色图集靠下并保留 12 px；文字通过 `textContent` 写入、`aria-live="polite"` 播报且不接收指针。
- 应用层角色呈现控制器接收目录、带 revision 的选择快照、图集预载端口和运行器工厂。图集解码并核对实际尺寸后才切换；旧实例在成功前保留，迟到加载和旧 revision 不能覆盖更新选择，同 ID 不重建。初次失败显示错误，切换失败保留当前角色并允许同 revision 重试。

## 原生选择与保存（Task 2 已接入）

- 入口先注册 selected-character-changed 监听，再调用 get_selected_character 获取 Rust 快照；前端验证已知 ID、非负安全整数 revision 与持久化状态，忽略旧 revision，销毁包括迟到监听建立。原生托盘“角色”子菜单和 select_character IPC 共用选择服务。
- Rust 是角色选择和持久化的唯一权威。character-preferences.json v1 由一个串行 IO 工作线程保存，成功后才提交有效选择与 revision；保存失败保留旧选择，未知已存 ID 回退但保留文件，损坏/未来版本本次只读并允许“仅本次有效”选择。原生 UI 更新释放锁后调度到主线程，不改变桌面窗口状态。
- atomic_file.rs 共享位置/角色两种 store 的同目录临时写、备份与替换，schema 校验留在各 store。退出拒绝新角色请求并取消未执行队列；未提交的在途写不发布迟到成功。细节见 ARCHITECTURE.md。
- 前端图集失败保留旧实例，错误显示 4 秒，诊断写日志；托盘再次选择相同角色产生新 revision 并可重试，不伪造 Rust 已回退。
- reminderCompleted 与 reminderSnoozed 要等后续提醒服务调用；本任务没有复制提醒时钟，也没有把动画或短句当作提醒完成证据。

## 后续角色引导提醒候选

用户在 Windows 试用后要求到期提醒由角色发起，并确认雷电将军采用克制正式的“将军”口吻。当前候选在角色目录中增加 `reminderDue` 动作入口及喝水、起身、眼睛、合并提醒的短句；三月七活泼亲近，雷电将军简洁克制。短句是本项目为提醒情境新写，不伪称原作语音。角色可采用经核对的短原作台词，但正式分发前须确认来源及使用范围。口吻参考[三月七官方介绍](https://www.hoyolab.com/article/31407362)和[雷电将军官方介绍](https://www.hoyolab.com/article/760383)，最终观感仍由所有者验收。

原生协调器只在自动提醒对白实际显示后通知主角色一次；手动查看、角色切换、页面重载及专注完成不重播到期动作。对白页订阅同一角色选择快照，显示当前角色头像、名字和该提醒的台词；完成／稍后仍交给 Rust 服务，角色目录不保存提醒时间。

## 验证与实机边界

- 自动测试覆盖目录/路径/帧/短句校验、one-shot 时序与优先级、手势取消和双击去重、原生拖动失败、短句轮换与清理，以及异步切换的乱序、失败、重试和销毁。
- TypeScript、Vite 构建、架构检查与打包准备验证前端结构和产物；Task 2 的 Rust 测试覆盖选择保存、只读、未知 ID、失败原子性、串行顺序、退出与迟到完成，同时重跑原 desktop 故障回归。Windows 本地检查不替代同提交双平台 CI/原生包、独立审查和 GUI 验收。
- 浏览器/单元测试不能证明透明原生窗口里的拖动手感、双击容错或 pointer capture 与系统拖动的真实协作。
- 两角色的最终视觉、动作观感和原创短句仍需所有者验收；自动测试只证明配置边界与确定性行为。
