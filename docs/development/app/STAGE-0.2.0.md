# March 7th App v0.2.0 阶段报告

日期：2026-09-18  
平台：Apple Silicon macOS  
状态：通过阶段验收

## 阶段目标

本阶段只处理一个功能闭环：让 March 7th 在被拖动时稳定播放左右移动动画，并彻底解决注视帧抖动问题。

不在本阶段加入点击动作、托盘菜单、点击穿透、自动启动、位置记忆或设置页面。

## 已完成行为

| 情境 | 当前行为 |
|---|---|
| 静止且鼠标位于角色中心死区外 | 根据真实鼠标位置选择 16 个注视方向之一 |
| 静止且鼠标位于中心死区内 | 播放六帧待机循环 |
| 向右拖动窗口 | 播放 `running-right` 八帧循环 |
| 向左拖动窗口 | 播放 `running-left` 八帧循环 |
| 仅上下拖动 | 沿用最近一次水平方向的移动动画 |
| 停止拖动 | 等待约 160 ms，再恢复鼠标注视 |

## Bug 根因

早期实现使用鼠标全局坐标减去窗口原点来选择注视方向。原生窗口拖动期间，鼠标坐标与窗口位置通过不同的异步路径更新，单次采样可能组合了不同时间点的数据，导致计算角度在相邻方向格之间反复跳变。

第一次修复尝试依赖 `startDragging()` Promise 表示拖动生命周期，但 WebView 和原生窗口拖动的事件时序并不适合作为持续拖动状态的唯一依据，因此仍可能提前恢复注视。

## 最终方案

Rust 采样命令现在一次返回：

- 鼠标相对当前窗口的位置
- 当前窗口的全局逻辑坐标

前端比较连续两次窗口坐标：

1. 窗口移动超过 `0.5 px` 时进入移动状态。
2. 水平位移为正时选择右移动，为负时选择左移动。
3. 移动状态中不读取或渲染任何注视方向帧。
4. 每次检测到窗口移动，将移动状态延长 `160 ms`。
5. 窗口稳定后恢复正常注视或待机。

移动动画使用现有 v2 图集：

- 第 1 行：`running-right`
- 第 2 行：`running-left`
- 每行 8 帧
- 帧间隔约 `90 ms`
