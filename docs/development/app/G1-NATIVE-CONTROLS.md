# G1 原生桌面控制实现记录

更新时间：2026-09-22

状态：代码已实现，技术批准与双平台 GUI 验收尚未完成；M0、M1 均未关闭。

## 已实现

- Rust 在应用启动阶段创建原生托盘；托盘构建失败会沿现有启动错误路径返回，不会把唯一窗口转为仅托盘常驻。
- 双平台菜单使用 `show`、`hide`、`reset-position`、`quit` 等命令 ID；当前集成候选在 macOS 另提供 `move-to-current-space`。菜单事件绑定在同一托盘而非 WebView 上，窗口隐藏后仍可处理。新菜单的 Mac Spaces 行为需以当前候选重新实测。
- 主宠物窗口从启动起配置为不聚焦、不可聚焦；“显示”和“重置位置”共用同一原生显示路径，在显示前再次确保窗口不可聚焦。锁定的 Tao 版本在 Windows 将该状态映射为 `WS_EX_NOACTIVATE`，在 macOS 通过 `canBecomeKeyWindow`／`canBecomeMainWindow` 拒绝成为关键窗口；仍需 GUI 验证其他应用正在输入时焦点不会转移。隐藏不请求焦点。
- 重置位置优先使用主显示器，缺失或查询失败时回退到当前显示器；基于显示器物理原点、物理尺寸及窗口实际外部尺寸居中，然后通过上述显示路径显示窗口。
- 托盘成功初始化后，主窗口关闭请求改为隐藏；托盘退出直接结束应用，未增加阻止应用退出的全局钩子。
- 菜单操作失败会把操作名和错误写入标准错误。位置计算与原生 IO 分离，并覆盖负原点、非零原点、窗口大于屏幕、普通居中和极值溢出边界。

## 当前验证与缺口

- Windows x64：锁定依赖下的几何单元测试已通过；完整 Rust、前端与静态检查结果以本次任务报告为准。
- macOS Apple Silicon：本分支尚未编译或运行单元测试。
- Windows 与 macOS：托盘图标、隐藏后菜单、关闭转隐藏、重置位置、多显示器与退出仍需 GUI 验收。
- Windows 与 macOS：让另一个应用的文本输入框保持输入状态，分别从托盘执行“显示”和“重置位置”，确认输入焦点未转移；同时确认不可聚焦的宠物窗口仍能接收主按钮拖动。

这些未验证项完成前，不把 G1 标为完成，也不据此关闭 M0 或 M1。
