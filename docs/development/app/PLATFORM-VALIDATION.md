# 跨平台验证指南

本指南定义如何生成可公开核验的工程记录，不宣布任何版本通过测试。适用代码、运行环境和结果必须由实际执行人填写。历史 Windows 参考见 [WINDOWS-HANDOFF.md](WINDOWS-HANDOFF.md)，项目门禁见 [CONTRIBUTING.md](../../../CONTRIBUTING.md)。

## 准备与自动检查

先按当前分支的 [App 说明](../../../march-7th-app/README.md) 配置环境，并记录 `git rev-parse HEAD`。在仓库根目录执行：

```sh
cd march-7th-app
pnpm install --frozen-lockfile
pnpm check
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --locked --manifest-path src-tauri/Cargo.toml
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

工具版本以当前分支的项目要求为准。缺少依赖、无法执行某个平台检查、失败或跳过时如实记录；不要填入未执行的通过结果。仅文档与模板变更可以说明实机行为测试不适用及理由，但不能借此为其他功能补签验收。

## 共享行为的实机清单

Windows 和 macOS 使用同一提交及同一份适用清单，分别记录环境和执行人。至少覆盖此次变更涉及的功能、失败路径和回归边界。

| 检查域 | 检查内容 |
| --- | --- |
| 生命周期 | 正常启动、显示、隐藏及退出；订阅和定时器的清理 |
| 角色基线 | 透明窗口、置顶、待机、注视、左右拖动和停止后的恢复 |
| 显示环境 | 屏幕数量、分辨率、缩放比例、DPI；具备设备时检查跨屏与混合 DPI |
| 平台行为 | 目标分支实际存在的托盘、窗口控制与恢复入口；macOS 桌面或空间切换 |
| 新增业务 | 仅对该提交实际存在且受改动影响的提醒、交互或持久化路径验收 |
| 分发变化 | 涉及安装包时核对提交身份、哈希、安装、升级、卸载和回退 |

没有多屏、另一平台或其他必要环境时写明设备缺口。计划能力不能标记为已经实现；CI 通过不替代窗口透明、原生操作、常驻观感等实机检查。

## 可公开的验收记录模板

```text
测试日期：
目标版本 / 分支：
完整提交 SHA：
平台 / 系统版本 / 架构：
显示器与缩放：
执行人：
清单版本或路径：
实际执行的命令及退出结果：
逐项实机结果（通过 / 失败 / 未测 / 不适用并说明原因）：
复现步骤和脱敏证据：
未覆盖项目、阻塞与已知限制：
另一平台同提交记录：
结论与适用范围：
```

含个人桌面、用户名、路径、配置或聊天内容的原始截图先保存在受限位置；公开侧保留脱敏截图、日志摘要、根因和可复现步骤。不能让私有附件成为理解结论的唯一依据。
