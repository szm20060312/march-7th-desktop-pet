# G7-B1：统一配置目录与可写实例协调

状态：执行计划，单一技术结果，不是导入导出完成。依据 PRODUCT-PLAN.md 的本地数据、唯一写入者、失败不伪装成功和稳定常驻要求。上游 G7-A 源码39d78bb已复审，新同提交CI运行中。用户授权持续完成独立开发；本计划不创建正式Goal，不受导入立即/重启生效偏好影响。

## 目标与非目标

三个现有原生服务从同一个明确的配置目录取得自己的固定文件路径；同一根目录只允许一个遵守此协议的可写实例。正常使用继续原有平铺文件与格式，异常时不换目录或重置数据。

不做导入导出、活动数据集指针、格式迁移、文件对话框、自动重启、跨进程唤醒窗口、自动启动或专注/任务。旧程序不采用锁协议，仍须先退出旧实例；文件锁不是外部工具访问控制。

## Global Constraints

- `desktop-state.json`、`character-preferences.json`、`reminders.json` 的位置、schema和原有业务/保存语义保持。只将原生setup的重复目录解析收敛到一个真实共享入口。
- 在任何角色/提醒/桌面写入工作线程、托盘和桌面控制服务启动前获取该目录的排他文件锁。锁持有覆盖整个应用生命周期；不要复制/提前释放持锁句柄。
- 固定锁文件 `instance.lock`，打开时不截断、不写PID、不删除。旧锁文件仍可在原持有者退出/崩溃后再次获得；不能靠删文件“解锁”。使用非阻塞try_lock。
- `WouldBlock` 是另一实例持有锁：第二实例正常结束，不启动业务写入者，不惊动现有实例，不尝试结束其他进程。其他IO/路径失败不能冒充已在运行。
- 无法安全取得可写根目录时，保持现有临时/只读降级能力：三服务均不能获得可写路径，不创建替代数据目录，不覆盖原配置。原有会话角色选择、提醒默认关闭/只读和位置不可保存提示如实保留，必要时给一个明确的原生状态说明。
- `--build-info` 仍在 Tauri/目录/锁/服务初始化前返回；版本查询不占用数据锁，也不创建配置。
- 单个 app_context/generate_context 保持；退出最后保存、窗口/提醒的停止与迟到回调围栏保持。没有原生GUI运行或真实用户目录试验。
- 无新第三方依赖/全局安装；标准File锁要求Rust1.89+，在Cargo/开发说明中明确最低版本。当前工具链1.98.1。只在临时测试目录验证。
- 无子代理、push、主线合并、发布或KB写入；协调者负责评审与远端验证。

## Task 1：实现并接入目录与写入资格

1. 核查 `lib.rs`、三个native setup和现有Store边界。新增窄的 `src-tauri/src/data_directory.rs`：标准库目录/锁逻辑、Ready/AlreadyRunning/Unavailable等明确结果、持有锁的对象和只读根路径访问。核心保持不依赖Tauri，便于真实子进程测试；不做通用Storage/插件注册框架。
2. 原生装配只调用一次 app_config_dir，确保目录存在并尝试排他锁。不改变现有文件名，也不解析/改写数据内容。可写对象交给Tauri managed state持有；Unavailable对象提供None路径，原因用固定诊断码或短说明，不输出配置内容。
3. `characters/native.rs`、`reminders/native.rs`、`desktop/mod.rs` 从该状态取得路径。继续各自schema和原子保存。不要重写三服务状态机或把数据目录模块变成新的业务状态源。
4. lib.rs启动顺序先取得资格，再依现有顺序初始化服务。Tauri2.11.5的SetupError封装不提供内部错误downcast；可用一个窄的启动结果标记区分受控的第二实例退出，避免比较错误字符串。第二实例不进入正常run回调/业务服务。真实其他setup错误仍按真实错误处理，不一概当成已有实例。
5. 不能为Unavailable又回到各服务的app_config_dir创建/写入路径；显式覆盖这条降级接线。现有data path调用者应只依赖新入口。文件锁作用于参与此约定的实例，不能据此宣称能拦截旧版或任意外部修改。
6. 关键行为先红绿：根目录/固定文件路径不变；有效锁下第二获取返回AlreadyRunning；关闭与异常子进程退出后可重获；锁文件存在但无人持有不误判；根目录是文件/路径不可用等返回Unavailable且不改原数据；持锁对象寿命与setup资格决定服务是否启动。使用实际OS锁，不只mock布尔值。
7. 为跨进程/异常退出编写窄的真实Rust/Node fixture并纳入双平台native regression workflow。不要用空断言/默认跳过的“helper test”充数。可以用现有Rust工具链编译直接复用std核心的临时helper；不启动真正桌宠GUI。
8. 运行受影响测试迭代，结束时一次Rust fmt/test/Clippy/build及新增真实fixture、架构/打包等相关检查。前端未变可复用上游140项与浏览器证据，列清复用范围。需要新的Windows release/--build-info无配置副作用检查时，保留旧包，用独立证据路径；Mac真实锁/退出和CLI由同提交CI补证。
9. 更新用户README、ARCHITECTURE、TODO、此阶段说明和统一回归清单：第二启动行为、无法写入的降级、旧版必须先退出、锁文件不可用来判断程序存在。不得声称双平台GUI或导入导出已验收。提交不push。

## 接口与验收自查

| 关系 | 验收要求 |
|---|---|
| 目录/锁核心→原生装配 | 三种结果分清，资格先于写入者 |
| 持锁对象→managed state→退出 | 不提前drop，进程结束能重获 |
| shared root→三服务 | 正常路径相同，Unavailable全部无写入路径 |
| CLI身份→应用初始化 | 身份路径没有目录和锁副作用 |
| 测试fixture→生产核心 | 真实OS竞争/释放，临时目录，双平台CI |
