# G4 双角色与互动实现计划

状态：执行准备。来源：已确认 PRODUCT-PLAN；用户已选择雷电将军并认可 candidate-v1 外观，授权实机验收待补时继续独立开发。M0/M1 的人工验收继续开放。

目标：托盘切换三月七/雷电将军，重启记住选择；单击和双击获得动作与短句回应，拖动保持可靠。角色切换只触及表现与角色选择，不修改桌面位置、未来提醒或专注状态。

## Global Constraints

- 离线内置角色，不新增账号、遥测、外部角色导入、AI 聊天或养成。
- Rust 是角色选择及持久化的唯一权威；TypeScript 管理动画、手势和呈现。业务模型无 DOM/Tauri 全局。
- 保留 G1/G2 托盘、非聚焦显示、穿透恢复、位置持久化和单个桌面工作线程；不得复制提醒时钟。
- 旧 Codex 封存资源不变。雷电资源沿用已审查图集，不重新生成，不把透明未用行当能力。
- 自动检查、浏览器预览、实机验收分别记录。两角色最终观感和台词验收仍由所有者完成。
- 不推送、合并主线或发布；不安装全局依赖。实施者不派生子代理。

## Task 1: 双角色目录、手势和情境回应

在已合并 G1/G2 与雷电资源的隔离分支实施。此任务仅交付前端行为，原生选择接入属于 Task 2。

1. 扩展 `src/domain/character.ts` 为已使用能力：保留 idle/movingLeft/movingRight/look，新增可选 wave/jump 动作与情境短句 `click`、`doubleClick`、`reminderCompleted`、`reminderSnoozed`。缺动作回退 idle；缺短句不显示文字。后三者中的提醒情境仅作为有类型可调用能力，不添加虚假提醒入口。
2. `src/characters/catalog.json` 为两角色唯一编译期数据来源，包含稳定 id/displayName/atlas/clips/look/phrases。`catalog.ts` 做完整校验并导出目录/default。三月七继续 id=march-7th；雷电 id=raiden-shogun。两者 atlas 都是192×208、8列11行，已有图集；idle row0 6帧280ms，右移动row1和左移动row2各8帧90ms，wave row3 4帧180ms，jump row4 5帧120ms，look row9起16方向。不可请求rows5–8。用测试验证动作行/帧范围、间隔、重复ID、路径及短句限制。现有 march-7th.ts 可作为兼容导出或迁移调用者，不保留第二份独立配置。
3. 预设原创短句，每个情境每角色2条，每条最多14个Unicode字符、单行、不含HTML。三月七轻快：点击“咱在呢！”/“今天也一起加油吧。”，双击“嘿，精神满满！”/“准备好出发啦！”，完成“好啦，继续慢慢来。”/“照顾好自己呀。”，稍后“好，等你方便的时候。”/“那咱先安静一会儿。”；雷电平和克制：点击“我在。”/“此刻，与你同在。”，双击“精神尚可。”/“稍作舒展，也好。”，完成“做得好，继续吧。”/“片刻休整，亦有益处。”，稍后“不急，依你的节奏。”/“待你方便，再作提醒。”。同情境按角色内顺序轮换，避免随机难以测试；不额外自主说话。
4. 扩展 PetModel 明确动作事件，优先级 movement > one-shot > look > idle。wave/jump 从首帧播放一次，按注入单调时钟计算帧，延迟帧直接赶到正确位置/结束，不因背景卡顿从头重播。移动中输入不排队；拖动/实际位移中止互动。结束回注视/待机，不能无限循环。保持现有移动/注视语义。
5. 手势拥有独立小模块与窄端口。仅主按钮：单击等300ms区分双击，第二次释放距第一次不超过300ms且位置相差不超过6逻辑像素为双击，仅触发一次jump；单击wave。按下至移动达到6逻辑像素即原生拖动一次，取消待处理点击/短句，不再因释放触发点击。忽略非主按钮、多指和非当前pointer；cancel/lost capture/blur/dispose取消未完成输入。原生拖动不得在pointerdown立即触发。pointer capture应在native drag前释放，避免互相截获；document/window层处理指针移出舞台的清理。可通过注入调度器测试，不使用真实等待。
6. `application/pet-runtime.ts` 保留幂等stop及迟到采样隔离，新增明确情境回应入口但不泄漏模型；可以返回含stop/respond的控制器并迁移调用者。调用者仍通过端口，main.ts仅装配。动作与短句同时回应，短句显示3秒，连续回应替换旧文本和取消旧定时器，拖动/stop/换角立即清除。
7. 在现有240×260主窗口内为短句预留顶部36px，192×208角色靠下留12px，文字不遮挡角色、不更改原生窗口尺寸。轻量横向暖白/深灰短句条、清晰细边、13px中文系统字体，暗色有对应配色，最多216px宽；不采用随机紫色渐变。文本使用textContent，pointer-events:none，不加交互按钮、不抢焦点；aria-live=polite。保留透明桌面背景。调整 CSS/HTML/DOM适配器，不引入UI框架。
8. 提供应用层角色加载/切换控制器接口供Task2接入，构造时接收目录、带revision的选中快照、图集预载端口及运行器工厂。先解码并验证图集实际尺寸再切换；成功前保留旧实例，成功后stop旧实例再启动新实例；迟到加载/快照不得覆盖更新选择，同ID不重建。初次失败显示可读错误，切换失败保留旧角色并可重试，销毁后迟到结果不写视图、不留定时器。原生选择状态与呈现错误分开，错误不能伪装成功。Task1入口可暂用默认快照；Task2会连接真实原生事件。不要提前建立通用事件总线。
9. 更改架构检查器以支持characters内JSON数据依赖，仍保留层级/循环/宿主隔离，不能简单跳过所有JSON路径检查。覆盖模型时序、手势取消/双击去重/原生拖动失败、短句清理、异步换角乱序/失败/销毁的真实回归测试；先红后绿关键行为。运行相关测试再做一次前端全检查，Rust无变更时复用既有结果。
10. 写 `docs/development/app/G4-CHARACTERS.md` 当前已实现/待原生接入/待实机边界，修正 ARCHITECTURE 中第二角色未选定等失效描述，保留历史基线标签。提交并报告测试命令与结果，不推送。

## Task 2: 原生选择、保存与完整接入

依赖 Task1 审查通过。技术合同以 Task1 实际接口为准，不改变本节用户行为。

1. Rust `characters/` 读取同一编译期catalog.json获取id/displayName，托盘角色子菜单展示两项互斥勾选。稳定默认来自目录的defaultId；禁止业务if(id==某角色)。菜单事件与有类型IPC共用选择服务，未知ID报错。选择不移动/显示/隐藏角色窗口、不改变穿透和其它应用状态。
2. 单独 `character-preferences.json` v1保存选中ID，Rust唯一写入。提取当前desktop/store中实际共用的同目录临时写、备份、替换为窄基础工具；schema校验留在各具体store，避免复制整套原子IO，也不引入通用repository框架。desktop原有故障回归必须仍通过。无配置默认三月七；未知ID使用默认但保留原文件直到明确用户选择；损坏/未来版本当次禁写、仍可临时换角并明确标为未保存。读写错误不泄漏原始内容。
3. 普通可写状态选择先完成保存再提交effective id/revision和通知；失败保留旧选择并在禁用菜单状态项展示失败。只读状态允许会话选择，状态明确“角色：仅本次有效”。后台串行IO，不在UI持锁等待，不产生每次点击一个永久线程；退出和迟到完成规则清楚，不影响desktop退出工作线程。快照包含selectedCharacterId、revision及持久化状态；事件与首次get快照通过revision对齐，不丢订阅前后变化，Frontend验证IPC。
4. main通过适配器订阅并读取真实选中快照，使用Task1切换控制器。监听注册后读取快照，忽略旧revision，dispose包括迟到监听建立。图集读取失败有可见短暂错误和可诊断日志，旧实例保留，后续相同选择也有重试通道，不伪造Rust已回退。
5. 更新架构、TODO、角色来源README的“尚未接入”描述，补双平台同清单：启动选择、重复切换、乱序、读写失败、两角色点击/双击/拖动、穿透托盘换角、不主动打扰。更新regression文档以当前构建能力为准，历史M0包仍以原提交文件为准。
6. Rust存储/未知ID/只读会话/失败原子性/串行选择与退出测试；前端事件快照乱序及销毁测试；完整前端check与Rustfmt/test/clippy/build。独立审查后控制者推送隔离分支跑同提交双平台CI和原生包，才记录技术验证。不得标记M2或G4人工验收完成。
