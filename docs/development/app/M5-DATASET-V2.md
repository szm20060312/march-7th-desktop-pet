# M5-A2a：四项数据集与本地备份 v2

本切片只建立专注状态的持久化载体；没有专注服务、计时入口、任务文本或新的界面。已有目录锁仍由 Rust 唯一持有。

## 启动与迁移

启动先验证活动指针、激活标记及待导入记录。旧 v1 待导入必须按原三文件摘要完成并移除收据，随后才迁移；清理失败进入保护，不用新记录覆盖旧收据。

旧平面目录及旧 v1 活动集复制到一个新目录，保留桌面位置、角色、提醒的原字节；缺失旧平面项才取各自默认值。专注补 `focus::model::Data::default()`（idle，从未开始）。原文件损坏、未来版本、不可读或目录协议不明确时不给服务可写路径，不把坏数据替换成默认。退役角色仍按已有 Store fallback 处理；新导入仍要求已知角色。

新目录固定包含 `desktop-state.json`、`character-preferences.json`、`reminders.json`、`focus.json`。四项分别写入并同步、回读验证，写入 v2 待激活记录，再原子替换 `active-data-set.json`，指针是唯一提交点。`focus.json` 不写入旧平面根目录或旧活动集。新空目录也直接初始化完整 v2。

故障前后的启动只能选择完整旧集或完整新集；不确定时进入保护状态。准备失败可能留下未引用的新目录，保留这些目录，不自动删除用户数据。旧三项与旧活动集保留；指针更新保留前一指针的 `.bak`，它只是恢复证据，不是自动降级指令。激活标记本身仍为 v1，活动指针与待激活记录采用 v2。

## 备份与预览

新导出固定是 `march7-local-backup` 的 schemaVersion 2，四项原字节参与 SHA-256。单份备份上限仍为 2 MiB，v1 三项总上限仍为 1 MiB；v2 四项总上限为 1 MiB + 4 KiB，其中 focus 独立上限为 4 KiB 并计入合计。这为原三项恰达上限的合法 v1 保留单会话空间，超过 focus 预算须显式版本化调整，不能静默截断。旧 v1 校验和仍只覆盖原三项；通过验证后补默认空 focus。v2 缺失、损坏或未来 focus 都拒绝，不静默重置。

专注尚无运行服务，导出从当前已选数据集读取、验证并冻结精确 focus 字节；不调用计时恢复逻辑。预览协议仅新增 `focus.status` 和 `focus.defaultedFromV1`，旧备份明确标记默认空状态。预览不携带任务文本、时钟锚点或路径。现有前端未接此摘要展示，留待后续 UI 切片；协议返回不等于界面已呈现。

确认导入只暂存四项；当前会话路径不变，下次启动整体切换。损坏暂存或写入失败保留旧指针、源字节与待处理证据。未知未来版本拒绝/保护，不尝试覆盖。

## 恢复旧版应用

升级前先退出所有旧实例，并保留旧版应用导出的 v1 备份。升级后不能把 v2 备份交给只认识 v1 的旧版；遵守协议的旧版会拒绝 v2 指针/待导入，不应手改版本号或删除指针强制继续。

确需恢复旧版时，退出新版，先单独保全整个当前配置目录，在独立或由操作者明确恢复的目录中，用对应旧版应用及它支持的备份恢复。不要让旧版直接覆盖 v2 配置，不自动降级；`.bak` 不是完整备份替代品。

## 验证边界

自动测试均用自建临时目录，包含原始 v1 fixtures、v1 pending 完成后升级、四项切换、焦点字节校验、缺失/损坏/未来版本、第四项写入失败、指针提交失败及重启恢复。Windows 本地检查见本次实施报告；macOS 同提交、真实备份导入 GUI、断电与安装/回退实机仍待验收。过程中的单个失败或静态检查不能代替这些验收。
