# 朋友试用记录与复盘

状态：模板已准备，试用尚未开始。空表、自动测试和 Agent 的体验不能计为朋友试用结果。

首轮准备邀请自己及少数朋友，目标约3—5人、覆盖Windows与Mac。先完成相应版本的真实基础验收，明确功能范围和已知问题，再约定两周的观察窗口。开始/结束时间由实际参与者确定，不能按代码提交日期自动起算。小样本用于发现问题，不用于宣称普遍效果。

## 一次简短记录

复制下面内容到自己选择的本地文件即可；应用不要求注册账号，也不会自动提交记录。参与者用代号，不必记录真实姓名、工作内容或任务文本。仅在有具体事件时记录，没开应用也如实写，不要求补齐每天的“打卡”。

```text
参与者代号：
日期／大致时段：
平台、版本／完整sourceCommit：
实际开启情况（大致时长，不清楚就写不清楚）：

有帮助的一次提醒或回应（没有也可）：
打扰的一次提醒或回应、当时如何处理：
今天为何继续开启、暂停或关闭：
故障或其它观察：
最想改的一件事：
```

点击“完成”的次数只代表操作，不等同于真实喝水、活动、用眼行为或健康改善。不需要把私人记录上传到仓库；由参与者主动决定分享哪些片段。若使用 GitHub 的“问题反馈”或“试用体验”模板，提交内容将公开可见。

## 两周结束后的共同复盘

先核对每个人实际用了哪些版本、多少天、是否遇到无法继续使用的问题。中途换版本时分开记结果，不能将旧版失败算作新版通过。使用天数短或中途退出也是信息，不自动视为无效反馈。

| 参与者代号 | 平台与版本 | 实际使用范围 | 具体帮助 | 主要打扰/故障 | 是否愿意继续及原因 |
|---|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 待填写 | 待填写 | 待填写 |

复盘结论由所有者结合参与者原始反馈填写：

- 继续投入：至少所有者和另一位参与者能给出持续帮助的具体例子，愿意继续使用，且没有未解决的严重稳定性问题。
- 有用但烦：优先调节奏和展示，暂不增加提醒种类。
- 喜欢角色、提醒无帮助：保留陪伴体验，暂停提醒扩张并共同复盘。
- 出现数据丢失、无法退出或明显妨碍工作：停止扩大试用，先修复并回归。
- 连续两轮针对性调整仍无明确价值：暂停该方向；不按路线图惯性堆功能。

```text
本轮已获得的真实证据：
仍缺的设备／场景／参与者反馈：
决定：继续／先修复／缩减／暂停某方向
决定理由及对应的具体反馈：
下一轮只验证什么变化：
哪些事项不进入下一轮：
共同复盘参与者及日期：
```
