- `windows/v0.2-baseline@a11d0d1` 已记录 Windows 单显示器 100%/150%/200% DPI 验证；Mac 基线见 [原阶段报告](STAGE-0.2.0.md)。

## 顺序

| 阶段 | 目标 | 关键出口 |
|---|---|---|
| M0 基线与架构 | 模块隔离、生命周期、角色配置、自动化回归 | 自动检查 + 双平台运行回归 |
| M1 / v0.3 常驻 | 托盘、可靠退出、穿透与恢复、位置持久化 | 用户能自己控制、找回和关闭桌宠 |
| M2 / v0.4 角色 | 两个真实内置角色、点击动作、情境短句、切换 | 共用逻辑下两个角色完整验收 |
| M3 提醒 | 三类内置提醒、分别完成、全局稍后、合并提示 | 闭环及睡眠/重启/穿透场景通过 |
| M4 朋友试用 | 双平台测试产物、两周真实使用 | 提醒有用且不烦；稳定为底线 |
| M5 迭代与分发 | 陪伴打磨 → 专注 → 任务；逐步公开测试 | 每次扩展有用户反馈和验收依据 |

M3 之后的版本号在阶段启动时确定。设置和持久化按使用它们的阶段交付；性能检查贯穿常驻和试用，不拖到最后。正式签名、自动更新和面向普通用户的分发，在小范围价值成立后继续推进。

## 双平台共同门槛

每个阶段必须列 Shared / Windows / macOS / QA。Windows 由所有者实测，Mac 由朋友或协作者实测；同一提交和清单，两边都通过才能关闭阶段。单平台测试构建必须标为预览，不能代替双平台完成。

每次版本发布需要：相关自动化检查通过、人工验收有记录、文档与状态一致、产物和代码可追溯、已知限制和回退方式明确。不移动已有版本标签，不改原 Codex 封存包。
